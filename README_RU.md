# Ikki

Приложение для macOS в строке меню, которое напоминает делать микро-перерывы — дыхательные упражнения, отдых для глаз, сброс моргания. Чтобы продолжать работать, а не изнашиваться.

`macOS 14+` · без зависимостей · без сети · без телеметрии

---

## Что делает

После рабочего интервала (по умолчанию 25 минут) Ikki присылает уведомление с тремя вариантами: начать перерыв, отложить на 5 минут или пропустить. Если начать, появляется небольшое плавающее окно с инструкцией. Когда перерыв заканчивается, таймер перезапускается сам.

Перерывы короткие (20–75 секунд) и основаны на конкретных исследованиях, а не на ощущениях:

- **Дыхание — циклические вздохи.** Стэнфордское исследование 2023 года (Balban et al., *Cell Reports Medicine*) показало, что 5 минут циклических вздохов снижают тревожность и физиологическое возбуждение лучше, чем медитация осознанности или другие дыхательные паттерны. Ikki использует ту же схему: двойной вдох через нос, затем длинный выдох.
- **Дыхание — квадратное и 4-7-8.** Оба паттерна замедляют частоту дыхания до ~6 циклов в минуту, что увеличивает вариабельность сердечного ритма (HRV) и активирует парасимпатическую систему (Lehrer & Gevirtz, *Frontiers in Psychology*, 2014).
- **20-20-20.** Рекомендация Американской академии офтальмологии. Исследования показывают, что при работе за экраном частота моргания снижается с нормальных 15–20 до 3–8 раз в минуту (Patel et al., *Ophthalmic and Physiological Optics*, 2020). Взгляд вдаль снимает спазм аккомодационной мышцы.
- **Сброс моргания.** Та же причина: осознанное моргание восстанавливает слёзную плёнку и убирает синдром сухого глаза от длительного фокуса.
- **Смена фокуса.** Чередование ближнего и дальнего взгляда расслабляет цилиарную мышцу. Механизм тот же, что в 20-20-20, но через активное переключение, а не пассивный взгляд.

Кроме техник, сам принцип коротких перерывов подкреплён исследованиями когнитивной утомляемости: Ariga & Lleras (2011, *Cognition*) показали, что редкие, короткие умственные паузы дольше поддерживают концентрацию, чем непрерывная работа.

Тип перерыва выбирается случайно из тех, что включены в настройках.

## Установка

> Готового бинарника пока нет — нужно собирать из исходников.

Требования: Xcode 15+, macOS 14+

```bash
git clone https://github.com/indi256s/ikki
open ikki/Ikki.xcodeproj
```

Собери и запусти схему `Ikki`. Приложение живёт в строке меню, без иконки в Dock.

## Настройки

| Параметр | По умолчанию |
| --- | --- |
| Рабочий интервал | 25 мин (пресеты: 20, 25, 40, 52 или своё) |
| Типы перерывов | Все включены |
| Дыхательная техника по умолчанию | Циклические вздохи |
| Звуковые эффекты | Вкл |
| Запуск при входе | Выкл |

Глобальное сочетание ⌥⌘B переключает таймер из любого приложения (пауза/продолжение или запуск, если простаивает).

## Устройство

Чистый Swift, без внешних пакетов. Для состояния использует макрос `@Observable` (macOS 14+), для интерфейса — SwiftUI, там где SwiftUI не дотягивается — AppKit (окно перерыва это `NSPanel`).

```text
Ikki/
├── Models/          TimerState, BreakType, BreathingTechnique, EyeTechnique, TechniquePhase, BreakTechnique
├── Services/        TimerService, NotificationService, BreakWindowController, SoundService, LaunchAtLoginService
├── ViewModels/      MenuBarViewModel, BreakViewModel, SettingsViewModel
├── Views/
│   ├── Breaks/      BreakContainerView, BreathingBreakView, EyeBreakView, BlinkResetView, FocusShiftView
│   ├── Settings/    SettingsView
│   └── Components/  PulsingCircleView, CircularCountdownView, AnimatedEyeView, PhaseLabel
├── Theme/           AppColors, AppTypography, AppSpacing, AppAnimations
└── Utilities/       AppConstants, UserDefaultsKeys, GlobalShortcutManager
```

Таймер привязан к системному времени (`fireDate: Date`), поэтому выдерживает App Nap и сон дисплея без накопления ошибок. Фазы перерыва работают так же — без накопления ошибок с плавающей точкой.

Обработка уведомлений сосредоточена в `AppDelegate` — он единственный `UNUserNotificationCenterDelegate`. Настройки хранятся в `UserDefaults` с типизированными ключами; `launchAtLogin` читает значение напрямую из `SMAppService`, а не из `UserDefaults`, чтобы не расходиться с тем, что пользователь мог поменять в Системных настройках.
